# Product

## Register

product

## Users

Владелец или руководитель, который ведет задачи по нескольким проектам: АШ, Ломбард, Часы, Смартстрой и новым направлениям. Пользователь работает в режиме регулярного контроля: быстро ставит задачи, назначает ответственных, смотрит дедлайны, проверяет выполнение и замечает наложения.

## Product Purpose

task-SEO помогает вести проектные задачи в одном статическом веб-интерфейсе: группировать их по проектам, назначать одного или нескольких ответственных, раскрывать хронологию подзадач, видеть календарь плана и факта, общий дашборд выполнения и перегрузок, быстрые ссылки на сайт и отчеты клиента, отчет по закупу ссылок из Google Sheets, контент-планы из Google Sheets, планы работ по клиентам и изначальный аудит нового клиента.

Первый релиз рассчитан на GitHub Pages и сохраняет задачи локально в браузере. Закуп ссылок автоматически читается из публичной CSV-выгрузки Google Sheets. Общее командное хранилище для задач можно подключить следующим этапом.

## Brand Personality

Воздушный, управленческий, собранный. Интерфейс должен ощущаться как мягкая стеклянная панель управления: легкий, визуально спокойный, но достаточно плотный для ежедневной работы.

## Anti-references

Не делать маркетинговый лендинг, тяжелую CRM, темный перегруженный таск-трекер, канбан вместо списка, сухую таблицу Excel, B2C-квиз или шаблонный фиолетовый dashboard без реальных рабочих состояний.

## Design Principles

- Рабочая плотность без тяжести: важные даты, статусы и ответственные видны сразу.
- Настройки один раз: проекты и ответственные добавляются в админке, а не вводятся руками в каждой задаче.
- Хронология раскрывает сложность, но не перегружает основной список.
- Перегрузки и наложения должны быть заметны до того, как задача сорвалась.
- Закуп ссылок должен склеиваться по клиентам в понятные проектные отчеты.
- Автошколы должны вестись в общем проекте `АШ`, без отдельных проектных карточек `АШ спб` и `АШ мск`.
- Контент-планы должны подтягиваться из Google Sheets и показывать темы по месяцам внутри проекта.
- Планы работ должны лежать рядом с проектом, показывать месячные пункты и быть видны в общей сводке.
- Изначальный аудит должен показывать два этапа: сбор вводных аккаунтом и SEO-чек-лист специалиста.
- Актуальные задачи и отчетные даты должны попадать в календарь без ручного повторного ввода.
- Внутри клиента должны быть быстрые кнопки на сайт и отчетные документы с видимой датой отчетности.
- Статический релиз не должен притворяться backend-системой: хранение локальное и честно обозначенное.

## Accessibility & Inclusion

Цель — читаемый интерфейс с клавиатурно доступными кнопками, формами и переключателями, достаточным контрастом текста, понятными статусами не только через цвет и поддержкой reduced motion.
