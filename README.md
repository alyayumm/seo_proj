# task-SEO

Статический трекер задач для GitHub Pages: проекты, ответственные, хронология, сворачиваемые клиентские блоки, календарь плана/факта, общий дашборд, быстрые ссылки на сайты и отчеты клиентов, отчет по закупу ссылок из Google Sheets, контент-планы, планы работ и изначальный аудит по клиентам.

Первый релиз сохраняет задачи в браузере через `localStorage`. Закуп ссылок читается автоматически из вкладки `План` таблицы `Закупка ссылок SEO — сводная` через публичный GViz endpoint. Приход и расход по оплатам читаются из Google Sheets, вкладка `SEo сайта`, и выводятся в общей вкладке `Оплаты` и внутри выбранного клиента в `SEO-проекты`. Автошкольные строки Автосити и Автоправо объединяются в общий проект `АШ`. Контент-план ПромТехМакулатуры также читается из Google Sheets и раскладывается по месяцам внутри проекта. Планы работ и чек-листы аудита привязаны как проверенные источники по проектам. Для общей командной базы задач следующим этапом можно подключить Google Sheets, Supabase или Firebase.

Актуальный встроенный срез задач обновлен на 17.08.2026: Промтех, Балт Паллет, Аквагард, Смартстрой, Ректоп и АШ.

## Яндекс Метрика

Статистика Метрики для вкладки `SEO-проекты` обновляется через GitHub Actions workflow `Update Yandex Metrika stats`. OAuth-токен нельзя хранить в коде или в `public`: добавьте его в закрытый секрет репозитория `YANDEX_OAUTH_TOKEN`.

Если счетчик не находится по домену сайта, добавьте секрет `METRIKA_COUNTER_MAP` в формате JSON:

```json
{
  "Промтех": 12345678,
  "Аквагард": 23456789
}
```

Скрипт сохраняет только готовую статистику в `public/data/metrika-stats.json`; секреты в сайт не попадают.

## Bitrix24

Интеграция Bitrix24 работает только через backend-выгрузку в GitHub Actions. Вебхук нельзя хранить в `src`, `public`, `.env` для фронтенда или вставлять в браузерный код.

1. В GitHub добавьте repository secret `BITRIX24_WEBHOOK_URL`.
2. Если у проекта Bitrix24 `SEO` уже известен ID, добавьте repository variable `BITRIX24_SEO_GROUP_ID`, чтобы не искать проект по названию.
3. Вебхук должен иметь права на чтение CRM, задач, пользователей и рабочих групп/проектов.
4. Workflow `Update Bitrix24 snapshot` сохраняет очищенный публичный срез в `public/data/bitrix24-snapshot.json`.

Скрипт получает пользователей, CRM-лиды, сделки, контакты, компании, пользовательские поля CRM, задачи только из проекта `SEO`, дедлайны и последние комментарии к этим задачам. Телефоны, email, адреса, реквизиты, приватные ссылки вложений и похожие чувствительные поля не публикуются в snapshot. Имена контактов по умолчанию скрыты как `Контакт #ID`; если это нужно поменять, включите `BITRIX24_INCLUDE_CONTACT_NAMES=true` только после проверки приватности сайта.

Комментарии задач ограничиваются переменными `BITRIX24_TASK_COMMENT_TASK_LIMIT` и `BITRIX24_COMMENTS_PER_TASK_LIMIT`, результаты задач - переменными `BITRIX24_TASK_RESULT_TASK_LIMIT` и `BITRIX24_TASK_RESULTS_PER_TASK_LIMIT`, чтобы не упираться в лимиты API. Если в новом интерфейсе задач Bitrix комментарии ведутся в чате задачи, старый метод комментариев может вернуть ошибку; она будет показана в панели `Bitrix24`, а задачи, результаты и CRM продолжат обновляться.

Так как вебхук уже был отправлен в чат, лучше выпустить новый вебхук в Bitrix24 и старый отозвать.
